# Phase 3 구현 및 측정 결과

2026-11-11 · 로컬 실행 · GitHub 변경 없음

## 구현 범위

- 입력 100개 파일, 중복 원문을 합친 99개 문서 → 18,266개 청크.
- 1,800 UTF-8 bytes 예산, 240 bytes 겹침. PDF 페이지·HWP/HWPX 섹션 및 원문 문자 위치 보존.
- 표 청크 8,538개, 일반 본문 9,725개, 시각 검수 전사 3개. reference view와 미검수 OCR 제외.
- 원문 비공백 4,750,597자 보존율 100%, 근거 684개 연결 성공, 출처 오류 0개.
- BM25, 문자 TF-IDF, weighted RRF, MMR의 로컬 저장·재로딩·문서 필터·별칭 지원.
- 세션별 사용자 선택/질문 이력, 모호한 문서 확인 요청, 전체 문서 청크 반환.
- OpenAI 임베딩 + 로컬 Chroma 연결 코드는 별도 옵션. 실 API 호출 0회.

## 평가 조건

설정과 검색기 선택은 dev 결과만 사용했습니다. 기본 방식은 BM25입니다. top-k=5, 후보 fetch-k=40, MMR lambda=0.75, 측정 k=5/10/20을 유지하고 설정·코드·인덱스·dev 결과 해시를 먼저 동결한 다음 holdout을 한 번 평가했습니다. holdout의 다른 검색기가 더 높은 항목이 있어도 기본 방식을 바꾸지 않았습니다.

아래 비율은 필수 인용문 하나의 비공백 문자를 상위 k개 청크의 합으로 전부 복원한 근거 비율입니다. 정답 문서 어딘가를 찾거나 인용문 일부와 겹치는 것만으로 성공으로 세지 않습니다. 문서 필터에는 실제 `context.selected_doc_ids`만 쓰고 정답 문서 ID나 정답 값은 검색 입력에 넣지 않았습니다.

### 사용자 선택 문서가 주어진 경우

| 방식 | dev Recall@5 | dev Recall@10 | dev Recall@20 | holdout Recall@5 | holdout Recall@10 | holdout Recall@20 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| bm25 | 59.6% | 71.9% | 83.1% | 56.5% | 71.0% | 74.2% |
| char_tfidf | 24.7% | 29.2% | 34.8% | 38.7% | 51.6% | 58.1% |
| rrf | 34.8% | 46.1% | 66.3% | 46.8% | 58.1% | 69.4% |
| mmr | 39.3% | 60.7% | 70.8% | 58.1% | 62.9% | 69.4% |

dev는 사실·비교 27문항/근거 89개, holdout은 18문항/근거 62개입니다. 전체 100문항을 모두 채점한 수치가 아닙니다.

### 문서 필터 없이 전체 99개 문서에서 검색

| 선택된 기본 방식 | dev Recall@5 | dev Recall@20 | holdout Recall@5 | holdout Recall@20 |
| --- | ---: | ---: | ---: | ---: |
| BM25 | 58.4% | 83.1% | 53.2% | 74.2% |

전체 비교는 `reports/dev_evaluation.json`, `reports/holdout_evaluation.json`에 기록했습니다. 원본 내용 SHA 기준으로 dev와 holdout 대상 문서는 분리했고, 검색 인덱스는 전체 99개 문서를 포함합니다. 청킹 보존 검사에는 684개 원문 근거를 모두 사용했으므로 외부 독립 벤치마크라고 부르지 않습니다.

## 검증

- 네트워크 없는 단위·합성 통합 테스트 136개 통과. 라이브 SDK 통합이나 LLM 품질 테스트와 구분합니다.
- 노트북 코드 셀 13개를 순서대로 실행하고 각 검증문을 통과했습니다. 실제 Jupyter 커널 자동 테스트가 아니라 동일 Python 프로세스의 셀 순차 실행입니다.
- 전체 문서 입력 경로에서 dev 요약 12문항, holdout 요약 8문항의 필수 근거가 모두 전달됐습니다. 요약문은 생성하거나 채점하지 않았습니다.

## 현재 한계와 이어갈 실험

현재 근거 Recall은 실무 완성 기준으로 충분하다고 볼 수 없습니다. 문자 TF-IDF는 의미 임베딩이 아니며, 이번 dev에서는 결합 검색보다 BM25가 우수했습니다. 추가 개선은 새로운 dev 실험에서 수행하고 현재 holdout은 다시 튜닝에 사용하지 않아야 합니다.

OpenAI API 키가 제공되지 않은 현재 환경에서 의미 임베딩·실제 Chroma 통합·비용·지연시간은 측정하지 않았습니다. 노트북 마지막 셀에서 공개 문서 한 개의 임베딩을 명시적으로 활성화한 뒤 새 dev 실험에서 비교할 수 있습니다. 기본 실행은 외부 API를 호출하지 않습니다.

원문 보존은 이미 파싱된 문자에 대한 검사입니다. 모든 PDF 그림과 표의 의미·열 관계가 추출됐다는 뜻이 아닙니다. 큰 표 행 314개는 byte 예산에 맞춰 나눴고, 반복한 첫 행은 원문 문맥일 뿐 열 제목으로 의미 검증하지 않았습니다.

후속 질문 검색의 규칙 동작은 테스트했지만 대화 정답률·근거 부족 판단 정확도는 측정하지 않았습니다. 생성 답변·인용 검증·요약 품질을 붙이는 다음 단계에서 별도로 평가해야 합니다.
