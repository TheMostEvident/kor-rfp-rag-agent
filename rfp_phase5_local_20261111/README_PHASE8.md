# Phase 8 — 로컬 파일럿과 운영 기록

Phase 6의 문서 범위·후속 질문·비교·출처 검증을 로컬 화면과 연결합니다.
기존 Python과 원문·인덱스를 그대로 사용합니다. 추가 UI 패키지 설치, 재색인,
전체 요약 재생성은 필요하지 않습니다. 기본 실행은 API 0회입니다.

## 실행

저장소 최상위에서 기존 가상환경을 활성화한 뒤 실행합니다.

```bash
git pull --ff-only origin main
python rfp_phase5_local_20261111/scripts/phase8_pilot.py --serve
```

터미널에 표시된 `http://127.0.0.1:8765`를 엽니다. 종료는 `Ctrl+C`입니다.
이미 사용 중인 포트라면 `--port 8766`을 지정합니다. 서버는 127.0.0.1에서만 실행하며,
여러 사용자가 함께 쓰는 배포 서비스가 아닌 단일 사용자용 파일럿입니다.
브라우저 여러 탭은 같은 서버의 대화·사용량을 공유합니다.

1. 사업명·기관으로 문서를 찾고 하나 이상 선택한 뒤 **선택 적용**을 누릅니다.
   기관·연도 필터는 정확한 값으로 지정하며 비우면 해제합니다.
2. **질문 제출**로 검색합니다. 기본 모드는 원문 후보만 보여 주며 생성 답변 정답률을 계산하지 않습니다.
   두 문서를 선택하면 비교하고, 같은 대화에서 후속 질문을 이어갈 수 있습니다.
   다른 사업을 명시해 문서가 전환된 경우 현재 대화 범위도 갱신됩니다.
3. 실제 생성이 필요하면 **답변 생성 설정**에서 API 전송을 허용할 문서를 선택하고,
   **실제 API 답변 생성**을 체크한 뒤 **선택 문서 API 설정 적용**을 누릅니다.
   그다음 질문을 제출해야 호출합니다. 기존 `.env`의 키를 읽으며 화면·실행 기록에는 키를 수집하지 않습니다.
   새 문서로 전환했을 때 허용 목록 밖이면 호출을 차단하므로 전송 문서를 다시 지정하세요.
4. 답변과 원문 인용을 대조합니다. 생성 또는 검증 실패 시 원인을 확인한 뒤
   **오류 확인 후 계속**을 눌러 다음 요청을 제출합니다. 자동 재시도하지 않습니다.
5. **이 답변 검토**에 검토자와 다섯 가지 판정을 기록합니다. 인용 검사 통과는 의미적 정답 승인이 아닙니다.
   **실행·검토 현황 갱신**은 현재 세션만 다시 집계합니다.

모든 문서를 API에 허용할 필요는 없습니다. 현재 사용할 문서만 지정하면 됩니다.
기관·사업명은 탐색 정보이고 답변의 사실 근거는 원문입니다.
저장된 전체 요약은 문서 하나를 선택해 **저장 요약 열기**로 조회합니다.
Phase 5의 최신 포인터·결과 지문·원문 SHA·전체 청크 연결을 재검사하며,
없는 요약을 부분 검색으로 대체하거나 자동 생성하지 않습니다.
다른 실행에 저장된 요약은 `configs/phase8.json`의 `summary_run`을 해당 실행 폴더로 지정하세요.

## 15번 노트북과 CLI

`notebooks/15_younggwan_phase8_pilot.ipynb`를 기존 커널로 Restart → Run All 합니다.
기본값은 로컬 준비 확인·합성 자료 회귀 테스트·원문 검색 한 턴이며 API 0회입니다.
기본 검색은 첫 대표 문서에서 일반적인 예산·기간 질문을 조회하는 동작 검사입니다.
개발 세트 재평가나 독립 평가 성적으로 취급하지 않습니다.

`RUN_LIVE_PILOT=False`로 Run All 한 뒤 실제 파일럿 문서 ID·새 질문을 입력하고
`RUN_LIVE_PILOT=True`로 다시 Run All 해도 됩니다. 실제 질문 셀만 재실행할 수도 있습니다.
기존 커널의 `pilot` 객체를 재사용하므로 같은 커널의 호출 누적값은 유지됩니다.
동일한 `PILOT_BATCH_ID`·실행 모드·질문 순번은 같은 제출을 가리키며 중복 호출하지 않습니다.
다른 질문이나 문서 조합으로 새로 실행할 때는 `PILOT_BATCH_ID`도 바꾸세요.
커널 Restart나 서버 재시작은 새 세션과 새 호출 상한을 시작합니다.

```bash
# 준비 확인만. 원문·인덱스 변경 없음, API 0회.
python rfp_phase5_local_20261111/scripts/phase8_pilot.py

# 문서 목록과 원문 검색. 실제 ID는 목록에서 선택합니다.
python rfp_phase5_local_20261111/scripts/phase8_pilot.py --list --keyword 사업명
python rfp_phase5_local_20261111/scripts/phase8_pilot.py \
  --doc-id 선택문서ID --question '예산과 과업기간을 조건과 함께 알려줘.'

# 명시한 문서에 한해 생성. 질문을 반복 지정하면 같은 대화에서 순차 처리합니다.
python rfp_phase5_local_20261111/scripts/phase8_pilot.py \
  --live --doc-id 선택문서ID --question '예산의 부가세 조건은?'

# 실행 후 검토 파일을 편집했다면, 출력된 특정 세션 폴더를 지정합니다.
python rfp_phase5_local_20261111/scripts/phase8_pilot.py \
  --report-session rfp_phase5_local_20261111/phase8_outputs/sessions/실행ID

# 합성 RFP를 쓰는 로컬 회귀 테스트. 실제 API 호출 없음.
cd rfp_phase5_local_20261111
python -m unittest rfp_phase8.test_pilot -q
```

## 운영 기록과 사용량

`phase8_outputs/sessions/<세션ID>/`는 Git에서 제외합니다.

| 파일 | 내용 |
| --- | --- |
| session.json | 원문·인덱스 지문, 세션 식별자, 실행 상한 |
| turns/<턴ID>/request.json | 생성 전에 저장한 사용자 질문·문서 범위·API 설정 |
| turns/<턴ID>/record.json | 답변·인용·실패 진단, 턴별 및 누적 사용량, 시간, 결과 지문 |
| turns/<턴ID>/human_review.json | 해당 답변 지문에 연결된 빈 사람 검토표 |
| turns/<턴ID>/feedback/*.json | 화면에서 저장한 검토 수정 이력. 최신 수정본을 집계 |

검토표를 직접 편집해도 됩니다. 화면에서 검토 수정본을 저장했다면 그 최신 수정본이 우선합니다.
검토자와 다섯 개의 true/false 판정이 모두 있어야 검토 완료입니다.
미판정은 null이며, 실패·미검토·대역 클라이언트를 실제 API 정답률로 승격하지 않습니다.
`records_complete`는 기록 저장 완료이고 `review_complete`는 사람 판정 기록 완료입니다.
검토 완료에 보완 필요 판정이 포함될 수 있으므로 통과 수와 실패 턴도 함께 확인하세요.

`configs/phase8.json` 기본 상한은 **세션 전체 8회·총 입력 600,000 UTF-8 바이트**입니다.
비교는 문서 수만큼 호출할 수 있으며 첫 호출 전에 전체 잔여량을 검사합니다.
대화 초기화·문서 변경·API 켜기/끄기·화면 새로고침으로 상한을 초기화하지 않습니다.
서로 다른 CLI 실행·서버·커널에는 각각 새 상한이 적용됩니다. 계정 전체 결제 한도는 아닙니다.

시간은 질문 처리 범위이며 인덱스 준비·화면 표시 시간을 제외합니다.
실제 요청·로컬 캐시·두 방식 혼합·대역·모델 미호출의 p50/p95와 표본 수를 나눕니다.
사용량이 확인되지 않은 실패는 `usage_unknown_attempts`로 남깁니다.
단가 기본값은 null이며 0달러로 표시하지 않습니다. 기존 단가를 자동으로 가져오지 않습니다.
단가를 별도로 설정할 경우 `input_per_million`, `cached_input_per_million`, `output_per_million`과
모델·확인일·출처를 기록하세요. 추정치는 청구서가 아닙니다.

요청 저장에 실패하면 API를 호출하지 않습니다. 응답 이후 저장에 실패하면 추가 진행을 중단하며
커널/서버의 `pilot.unsaved_record`에 결과를 유지합니다. `request.json`만 남은 턴은
`incomplete_turns`로 표시하므로 정상 완료로 판단하지 않습니다.
저장 공간 문제를 해결한 뒤 화면의 **오류 확인 후 계속** 또는
`pilot.resume_after_error()`를 실행하면 수신한 결과 저장을 먼저 재시도합니다. 모델을 재호출하지 않습니다.

## Phase 7 인계와 파일럿 완료 기준

Phase 7 개발 세트의 원문 확보 130/141, 문서 범위 71/71과 대표 6턴 확인을 유지합니다.
남은 11개 근거 구간과 저장 요약이 없는 개발 사례 9건은 알려진 제한 사항입니다.
이번 파일럿 코드가 이 성적을 새로운 표본에서 재현했다고 주장하지 않습니다.
Phase 7의 원래 실행에 연결된 사람 검토표를 Phase 8 기록으로 대신 채우지 않습니다.

다음은 실제 사용자가 새 질문과 문서로 수행할 완료 조건입니다.

- 실제 사용 흐름에서 문서 선택·질문·후속 질문·비교·근거 부족·저장 요약 조회를 확인합니다.
- 검토자가 금액·VAT·기간 기산점·안정화 포함 여부·예외·근거 부족을 원문과 대조하고 판정을 기록합니다.
- 실제 요청의 지연·토큰·실패와 캐시 사용을 확인합니다. 적은 표본의 p95는 운영 보장으로 해석하지 않습니다.
- 독립 평가를 하려면 개발에 사용하지 않은 문서·질문과 독립 정답 근거를 별도로 확보하고,
  해당 표본을 확인하기 전에 평가 기준을 고정합니다. 현재 자유 입력 질문의 신규성은 `unverified`입니다.

Phase 8 구현·동작 검증과 실제 사용자 파일럿·독립 품질 검증은 별도 상태로 보고합니다.
이 단계에서는 원문 재수집·모델 학습·외부 배포·모든 요약의 유료 생성을 수행하지 않습니다.
