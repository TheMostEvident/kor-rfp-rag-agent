# 입찰메이트 RFP RAG — Phase 2 로컬 문서 처리

원본 PDF·HWP·HWPX를 읽고 본문·표·출처 위치·원본 버전·처리 실패를 공통 JSON으로 보관합니다. OpenAI API 키 없이 실행하며 GitHub·Drive·문서 저장소에 쓰는 코드는 없습니다.

## 시작

1. ZIP을 풉니다. `data/raw`에 공개 RFP 원본 100개가 포함되어 있습니다.
2. 기존 가상환경에서 필요 패키지를 설치합니다: `python -m pip install -r requirements-notebook.txt`.
3. `notebooks/03_younggwan_phase2_ingestion.ipynb`를 열어 위에서부터 실행합니다.
4. 기본값은 동봉된 새 파싱 결과를 검증해 읽습니다. `REPARSE_FROM_ORIGINAL=True`로 바꾸면 같은 원본을 파서로 다시 처리합니다. PDF 전체 처리는 환경에 따라 수 분 이상 걸립니다.

파서 자체는 `requirements.txt`의 pypdf와 PyMuPDF를 사용합니다. HWP/HWPX는 표준 라이브러리로 처리합니다. 숫자 보강용 로컬 OCR은 선택 기능이며 Tesseract 명령이 설치되어 있을 때만 실행합니다. 한국어 OCR 모델 설치나 원격 OCR 전송은 자동으로 실행하지 않습니다.

## 파일

| 경로 | 용도 |
| --- | --- |
| `local_ingest/` | 형식 판별·파싱·표·해시·출처 대조·품질 점검 |
| `data/input_manifest.json` | 파일명·ID·원본 SHA256·로컬 상대경로·중복 관계 |
| `data/raw/` | 원본 파일 100개. 파서가 내용을 변경하지 않음 |
| `data/processed/documents.jsonl` | 파일별 새 파싱 결과 및 경고·실패 |
| `data/processed/indexable_blocks.jsonl` | 동일 내용은 한 번만 포함한 본문과 검수 전사. 다음 청킹의 입력 |
| `data/processed/tables.jsonl` | 표 행·열·병합·원문 위치. PDF는 후보/미해결 상태 보존 |
| `data/reviewed_transcriptions.json` | 실제 원본 이미지와 대조한 버전 고정 전사 |
| `eval/` | Phase 1 정답 및 별도 원본 검수 회귀검사 |
| `reports/` | 전체 파싱 결과, 근거 대조, 표본 검수와 남은 검수 목록 |
| `tests/` | 손상·병합·출처 혼동·해시 변경·캐시·수동 전사의 의미 있는 테스트 |

`python -m unittest discover -s tests -v`로 패키지 루트에서 테스트합니다. 선택 OCR 테스트는 로컬 Tesseract가 없으면 건너뜁니다.

## 출처 규칙

PDF는 물리 페이지, HWP는 BodyText 섹션·문단·레코드 위치, HWPX는 원문 XML 섹션·문단·표 셀 좌표를 사용합니다. HWP/HWPX 내부 위치는 인쇄 페이지 번호가 아닙니다. 문서 ID와 원본 SHA256을 함께 보존하므로 같은 문구가 다른 문서에 있다고 정답 근거로 빌려오지 않습니다.

`blocks`는 다음 청킹에 사용할 본문입니다. HWPX의 `reference_blocks`는 새 원본 XML에서 다시 만든 인용 대조용 섹션 보기이며, 일반 본문과 함께 인덱싱하지 않습니다. 중복 파일 한 쌍은 보존하면서 같은 내용의 본문은 한 번만 저장합니다. 구조화 표도 따로 보관하므로 다음 단계에서 페이지 본문과 표를 모두 단순 합쳐 이중 인덱싱하지 않도록 처리합니다.

## 숫자와 표의 품질

본문 추출이 성공해도 PDF의 도형으로 그린 숫자가 빠질 수 있습니다. 실제 한국예탁결제원 문서 물리 3페이지의 사업명 단계, 수행기간 16개월, 예산 71,620,000,000원 이내(부가세 포함)가 해당했습니다. 원본 렌더를 확인한 세 구간은 `reviewed_visual_transcription` 출처로만 보강하며, 자동 추출 성과로 집계하지 않습니다. 전사는 원본 SHA256이 일치하고 시각 검수 상태가 있을 때만 적용됩니다.

선택 로컬 OCR은 숫자 후보·좌표·신뢰도를 별도 보고서에 남기며 항상 `unreviewed`입니다. OCR 결과를 자동 확정 정답이나 일반 추출문에 조용히 섞지 않습니다. 숫자 공란 경고가 발생한 17페이지도 모두 직접 대조했습니다. 11페이지는 실제 작성용 빈 서식, 4페이지는 읽기 순서 문제, 1페이지는 정규식 오탐이었으며, 실제 벡터 숫자 누락은 위의 1페이지였습니다. 빈 서식에 다른 사업의 숫자를 채우지 않았습니다.

기본 표 추출기가 누락했던 비고 셀 등은 실제 원본 표본과 대조하는 회귀검사로 확인합니다.

HWP/HWPX의 표는 내부 좌표를 사용하고 결정할 수 없는 좌표는 추정하지 않습니다. PDF 표는 선·좌표에서 찾은 후보이며 표지 프레임이나 도식이 섞일 수 있습니다. 모순되는 span은 미확정으로 남깁니다. 표 후보 개수를 정확한 원문 표 개수로 표현하지 않습니다. `reports/review_queue.json`은 추가 확인이 필요한 페이지·표·문자 문제를 담습니다.

## 평가의 의미

Phase 1의 684개 근거 연결을 **새 원본 파싱 결과**에서 찾습니다. 원문 일치, 공백 정규화 일치, 위치 후보 중복, 해시 불일치와 누락을 따로 집계합니다. 시각 검수 전사와 선택 OCR은 이 자동 인용 복구율에 합산하지 않습니다. 원문 인용 복구는 검색 재현율이나 LLM 답변 정확도가 아닙니다.

시각 검수는 대표 PDF 5개 물리 페이지와 별도 HWP 원문 대조를 포함한 표본입니다. 전체 문서의 모든 그림·표·시각적 의미를 검수했다는 뜻은 아닙니다. 원문 자체의 총액/세부액 또는 예산 적용기간 충돌은 임의 수정하지 않고 유지합니다.
