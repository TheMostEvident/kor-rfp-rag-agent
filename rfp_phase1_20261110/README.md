# 입찰메이트 RFP RAG Phase 1

2026-11-10 기준, 사용자가 지정한 공개 RFP 100개 파일(내용 기준 99개)에 대한 요구 명세와 평가 기준입니다. 실제 RAG 구현·성능 측정은 이후 단계입니다.

## 시작

1. 압축을 풉니다.
2. `notebooks/02_younggwan_phase1_acceptance.ipynb`를 Jupyter에서 엽니다.
3. 위에서부터 코드 셀을 실행합니다. Python 3.10 이상과 표준 라이브러리만 사용하며 API 키는 필요하지 않습니다.
4. 대표 개발 사례 10개의 질문·기대 결과·원문 근거를 읽습니다. 업무 관점에서 바꾸고 싶은 질문은 마지막 검토 셀에 의견으로 남깁니다.

명령행 점검은 패키지 루트에서 `python phase1_tools.py`를 실행합니다.

## 평가 자료 사용

사실 확인 25, 전체 요약 20, 문서 비교 20, 후속 대화 20, 불확실성 대응 15개입니다. 후속 대화는 64턴이므로 실제 질문 및 API 호출 수와 100개 사례 수를 동일시하지 않습니다.

동일 SHA256의 사본은 같은 분할에 두었습니다. 개발과 최종 평가 사이에 같은 원문 내용이 겹치지 않습니다. 이 패키지는 독립 제3자가 숨겨 둔 벤치마크는 아니며, 최종 평가 결과나 정답을 보고 조정했다면 그 사례를 개발용으로 전환하고 새 최종 평가 자료를 마련합니다.

모델 입력에는 `required_facts`, `expected_value`, 정답 인용, `expected_doc_ids` 등을 넣지 않습니다. `runtime_case`는 실행기용 사용자 입력만 추립니다. 실행기는 대화의 사용자 발화를 한 턴씩 보내고 모델이 실제로 생성한 이전 답변으로 이어갑니다. 합성 장애의 `context.tool_results`는 테스트용으로 주입하는 도구 결과이며 실제 장애 기록이 아닙니다.

`not_established_from_reviewed_text`는 검토한 텍스트에서 확정할 근거를 확보하지 못한 항목입니다. 원본에 조건이 없다는 확정으로 바꾸지 않습니다. 정답 핵심 사실 목록은 원문 모든 조항을 대신하는 완전한 요약이 아닙니다.

## Phase 2 인계

원본은 [mid-project-rfp-public](https://drive.google.com/drive/folders/1VfyGojWnYxYNM1wAqKfl-P2FcHkAivMP)에 있습니다. 이 패키지에는 원본 바이너리 대신 평가용 추출 본문이 들어 있습니다. 실제 파서는 원본 파일로 검증합니다.

확장자는 `.hwpx`이지만 실제 HWP5인 1개와, 본문 추출 중 UTF-16 불량 문자 1개를 치환한 1개를 다시 확인합니다. 표·그림·구간 누락, PDF 물리 페이지 및 HWP 내부 위치 추적을 검증한 뒤 청킹으로 넘어갑니다.

기존 10개 문서와 25문항이 들어 있는 이전 `01_...` 노트북은 이번 평가 기준에 사용하지 않습니다. GitHub 변경은 하지 않았습니다.

문서의 법령·참가자격은 해당 RFP에 기재된 요구를 요약하는 대상으로 다룹니다. 이 평가셋은 현행 법률의 별도 해석이나 최종 입찰 적격성 판단을 검증하는 자료가 아닙니다.
